Agentic Coding
最佳实践指南

从“氛围编程 (Vibe Coding)”的黑盒玄学，走向系统化的工程实践。在复杂软件工程中，依靠上下文治理与精确控制，突破模型能力的边界。

Vibe Coding (氛围编程)

只看结果不看过程的“黑盒”模式。依赖直觉，缺乏控制。在处理真实世界软件工程的复杂度时，往往因上下文丢失而导致不可维护。

Agentic Coding (代理编程)

系统化的工程实践。强调上下文的精确管理、原子化的工作流以及对模型边界的清晰认知。

基础层

结构化提示词

准确性优先

拒绝模糊指令。使用标准结构（Role, Context, Instruction, Constraint, Output）构建 Prompt。

分层配置管理

利用工具特性进行分级存储：

  • 公司级/全用户级 (规范)
  • 项目级 (特定架构/依赖)
核心层

上下文治理

信噪比控制

理解上下文窗口限制与召回率的关系。无论是 200k 还是 2m，过多的无关信息都会降低推理质量。

显式引用 (Reference)

不要让 AI 猜。手动将最重要的信息注入主流程：

@Docs @Interface @Utils

定期重置

单次任务结束后及时清空上下文 (New Chat)，防止幻觉累积。

执行层

编码工作流

原子化 (Atomic)

一次只做一个功能点。每完成一个小闭环立即进行 git commit。保持“半自动”而非“全自动”。

及时止损 (Undo > Fix)

如果 AI 跑偏或代码越改越乱，不要试图修复它。立即回退 (Discard) 状态，优化 Prompt 后重试。越涂越黑会导致上下文彻底污染。

边界意识

感知当前模型的逻辑推理上限。对于超复杂的重构，将其拆解为多个微任务分步执行。

Agentic Coding 是一种人机协作的纪律，而非对机器的盲目信任。
